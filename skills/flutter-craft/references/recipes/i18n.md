# Internationalization (i18n) Recipes
Best practices for localizing Flutter apps using `flutter_localizations`, ARB files, and the `intl` package.

**Use `flutter_localizations` and code generation via ARB files instead of custom map solutions.**
- **Reason:** Provides compile-time safety for localization keys, native support for plurals/genders, and integrates easily with external translation management systems (TMS).
```yaml
// Bad (in pubspec.yaml or custom maps)
// Map<String, String> translations = {'en': {'hello': 'Hello'}};

// Good (in l10n.yaml)
arb-dir: lib/l10n
template-arb-file: app_en.arb
output-localization-file: app_localizations.dart
```

**Always use placeholders in ARB files instead of concatenating strings in Dart.**
- **Reason:** Sentence structure and word order vary wildly across languages. Translators must be able to move variables around within the sentence.
```json
// Bad (app_en.arb)
{
  "greetingPrefix": "Hello ",
  "greetingSuffix": ", welcome back!"
}
// Dart: Text('${l10n.greetingPrefix}$name${l10n.greetingSuffix}')

// Good (app_en.arb)
{
  "greeting": "Hello {name}, welcome back!",
  "@greeting": {
    "placeholders": {
      "name": {
        "type": "String",
        "example": "John"
      }
    }
  }
}
// Dart: Text(l10n.greeting('John'))
```

**Never store localized strings in state variables or view models outside the build scope.**
- **Reason:** If the user changes the system language while the app is running, statically stored strings will not update. Fetching from `AppLocalizations.of(context)` inside `build()` ensures the widget rebuilds with the new locale.
```dart
// Bad
class _MyScreenState extends State<MyScreen> {
  late String title;
  
  @override
  void initState() {
    super.initState();
    // Will not update on locale change!
    title = AppLocalizations.of(context)!.homeTitle;
  }
}

// Good
class _MyScreenState extends State<MyScreen> {
  @override
  Widget build(BuildContext context) {
    // Rebuilds automatically when locale changes
    final title = AppLocalizations.of(context)!.homeTitle;
    return Text(title);
  }
}
```

**Use the `intl` package for formatting dates, numbers, and currencies.**
- **Reason:** Avoids manual formatting logic that breaks across locales. The `intl` package automatically adapts to the active locale's conventions (e.g., decimal commas vs. periods).
```dart
// Bad
final dateStr = '${date.day}/${date.month}/${date.year}';
final priceStr = '\$$price';

// Good
final dateStr = DateFormat.yMMMd(Localizations.localeOf(context).languageCode).format(date);
final priceStr = NumberFormat.currency(locale: Localizations.localeOf(context).languageCode, symbol: '\$').format(price);
```
