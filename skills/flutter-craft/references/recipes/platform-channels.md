# Platform Channels Recipes
Production standards for Flutter-to-Native interop using Method Channels, Event Channels, and Pigeon.

**Use `pigeon` for all non-trivial platform integrations instead of raw `MethodChannel`.**
- **Reason:** Raw method channels rely on string-matching and unchecked `dynamic` types, leading to silent runtime crashes. Pigeon generates type-safe interfaces for Dart, Swift/ObjC, and Kotlin/Java, catching API mismatches at compile time.
```dart
// Bad (Raw Method Channel)
final channel = MethodChannel('com.example.app/battery');
// Prone to typos, requires manual casting, and silent failures if native side changes
final int level = await channel.invokeMethod('getBatteryLevel', {'type': 'detailed'});

// Good (Pigeon)
// Define in pigeon_schema.dart:
@HostApi()
abstract class BatteryApi {
  int getBatteryLevel(BatteryRequest request);
}

// Generated usage in Dart:
final api = BatteryApi();
// Fully typed, compile-time safe
final int level = await api.getBatteryLevel(BatteryRequest(type: 'detailed'));
```

**Abstract platform channel calls behind a service interface or repository.**
- **Reason:** Prevents platform-specific implementation details from bleeding into the UI/Business logic. Allows easy mocking for tests without needing native integration.
```dart
// Bad
class BatteryWidget extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return FutureBuilder(
      future: MethodChannel('battery').invokeMethod('getLevel'),
      builder: (context, snapshot) => Text('${snapshot.data}'),
    );
  }
}

// Good
abstract class BatteryService {
  Future<int> getLevel();
}

class NativeBatteryService implements BatteryService {
  final _api = BatteryApi(); // Generated by Pigeon
  
  @override
  Future<int> getLevel() => _api.getBatteryLevel();
}
```

**Use `EventChannel` for continuous streams of native data rather than polling with `MethodChannel`.**
- **Reason:** Polling consumes unnecessary CPU cycles and can miss rapid events. `EventChannel` natively bridges to Dart `Stream`, providing efficient, push-based updates for things like sensors or location.
```dart
// Bad
// Polling a method channel on a timer
Timer.periodic(Duration(seconds: 1), (timer) {
  channel.invokeMethod('getLatestLocation');
});

// Good
final eventChannel = EventChannel('com.example.app/location_updates');

// Listen natively as a stream
StreamSubscription subscription = eventChannel.receiveBroadcastStream().listen((data) {
  print('New location: $data');
});
```

**Handle `PlatformException` and `MissingPluginException` explicitly.**
- **Reason:** Native code can fail in ways Dart doesn't expect (e.g., missing permissions, unsupported hardware). Unhandled exceptions will crash the app or break the async flow.
```dart
// Bad
final result = await channel.invokeMethod('doNativeWork');

// Good
try {
  final result = await channel.invokeMethod('doNativeWork');
} on PlatformException catch (e) {
  // Handle specific native errors (e.g. permission denied)
  logger.error('Native error: ${e.code} - ${e.message}');
} on MissingPluginException catch (e) {
  // Handle case where native implementation is missing (e.g., running on unsupported platform)
  logger.error('Plugin not implemented on this platform');
}
```
